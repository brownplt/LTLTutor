# Changelog (Feb 2025 and later)

This document summarizes notable updates since February 2025, with commit dates from the repository history for context.【728428†L1-L48】

## 2026-07
- **UX (2.1.8):** Stepping through a trace no longer redraws the page. Every trace state used to be rendered as its own copy of the formula tree, and a step cross-faded between two of them: for 250ms both copies were `display: block` inside a `flex-wrap` container, so the stepper occupied two rows and everything below it — the rule, the "different trace" button, the footer — was shoved down and snapped back on every click. The incoming copy also rebuilt its trace diagram from scratch (`TraceRenderer.render` clears the container) even though the diagram is identical at every step bar the highlight, and a 1s `flashHighlight` animation fired over the tree each time. Between the three, a step read as a page reload. Only two things actually differ between steps, so only those change now: the `tree-sat`/`tree-unsat` class on each node of a single tree, and which state carries the highlight. `TraceSatisfactionResult.getStepperViewData` sends the tree once plus one truth vector per state, addressed by a new `data-node-index` emitted in the same pre-order `getAllSubformulae` walks; `TraceRenderer.setHighlight` moves the highlight by toggling attributes on the existing SVG (every state gets a `CURRENT` badge at render time, hidden but for the current one), so nothing is created, measured or resized. Verified in the running app: document height, button position and the SVG element itself are unchanged across all steps, with no network requests. The 250ms transition also gated input — presses inside the window were dropped, so holding an arrow key lost most of them — and that guard is gone, so stepping keeps up with the keyboard. The empty stepper tab now says so, matching the Table and Matrix tabs, and the arrow buttons carry `aria-label`s rather than relying on `title` over an icon.
- **UX (2.1.8):** Removed the "No further feedback is currently available. We recommend stepping through the trace to see where/if it diverges from the formula." message from trace-satisfaction yes/no questions. It was the fallback for the half of those questions whose trace genuinely satisfies the formula (`TRACESAT_YES_PROBABILITY = 0.5`), where there is no misconception formula to contrast against — but it has been stale since per-state feedback landed in 2.1.6: it printed *below* a paragraph that already explains the verdict ("This trace **does** satisfy the formula… a trace satisfies the formula exactly when it holds from the very first state"), and its step-through recommendation duplicated the "Want to see it step by step?" stepper button below it. Such questions now carry no predetermined feedback (`feedback` is `None`; both templates already guarded on it). The "No" case keeps its contrastive feedback, which names the formula the trace *does* satisfy — something the per-state marks don't say. If the per-state block can't render (SPOT evaluation fails, or the state count doesn't match the drawn trace), `displayTraceSatFeedback` still returns silently, so those rare cases now show the verdict and the stepper button alone.
- **Bugfix (2.1.6):** The trace diagrams inside misconception explainers never rendered. Explainers are shown in the "recommended review" card on the home page, but `index.html` was the one page emitting `.trace-diagram` markup without loading `tracerenderer.js`, so the diagrams stayed empty `<div>`s — leaving the Finally explainer ending on "Thus both these traces satisfy `F p`:" followed by nothing, and the Until explainer missing the trace its closing sentence refers to. It looked intermittent because only two of the eight explainers (`implicitf`, `exclusiveu`) illustrate the operator with traces, and the card shows one explainer drawn at random from the student's top two misconceptions. The home page now loads the renderer and runs a render pass. The three copies of that pass (home page, exercise questions, answer feedback) are now one `TraceRenderer.renderAll(root)` helper, so a page that emits trace markup only has to call it.
- **UX (2.1.5):** The "unclear sentence" report control on english-to-LTL questions no longer reads as a heading for the answer options. It was a bold rust question ("Is this English sentence confusing or unclear?") sitting an equal distance from the stem above and the radio list below, so it grouped with neither; its `.row.ml-2` wrapper also pulled it left of the stem's text edge, since Bootstrap's `.row` sets `margin-left: -15px` and `ml-2` only partly cancels it. It is now a quiet caption-style link reading "Report unclear wording" (imperative, so it cannot be mistaken for the question to answer), tucked under the sentence with asymmetric spacing (about 4px above, 18px below) that groups it with the stem. Being quiet means losing the color signal, so it carries a permanent underline rather than color alone (WCAG 1.4.1), and uses `--ink-2` at 8:1 rather than the muted `--ink-3`, which is 4.17:1 on the card and under AA for small text; color returns on hover and focus. The control stays a sibling of `.actualQuestion`, so its label never leaks into the logged `question_text`. The modal, its route, and its payload are unchanged.
- **A11y (2.1.5):** The keyboard focus ring now actually appears on that control. The theme's global ring is a zero-specificity `:where(...):focus-visible` rule, which Bootstrap's `.btn:focus { outline: 0 }` outranks on any button, so the only focus signal would have been a color shift; `.btn.unclear-flag:focus-visible` restates it at (0,3,0). The letter key also uses `--ink-2` (8:1) rather than `text-muted` (`--ink-3`, 4.17:1 on the card, under AA at that size), since the key is the only place the letters in the options are defined. The rest of the page still pairs `text-muted` with `small` at that sub-AA ratio (card-header meta, question description); that is pre-existing and wants its own pass.
- **Bugfix (2.1.4):** Themed english-to-LTL questions now state what their letters mean. The sentence was in words ("the document is open") while every answer option was in letters (`d`, `c`), and nothing connected the two, so a student also had to guess that `d` names the document being *open*, not the document, which has more than one state. Each themed question now carries a key listing only the literals its formula uses (`d`: the document is open), rendered above the sentence. Themed responses logged before this fix measured LTL reading confounded with guessing the naming, and both themed arms are affected; per-arm analyses spanning the change should be segmented. The abstract control arm is untouched, since it quotes its literals in the prose already and there is nothing to look up.
- **UX (2.1.4):** A deontic english-to-LTL question now asks its scenario in the question prompt rather than stacking it above the sentence: the card header reads "You are auditing access to a confidential document. Which of the following LTL formulae best represents this policy?", built from the theme's `preamble` and new `rule_noun` fields. Previously the scenario and a "Company policy:" lead-in were glued onto the front of `question` with newlines and rendered at heading size, giving the framing the same visual weight as the property to formalize. The card body is now the letter key plus the one sentence to formalize. Other arms keep the generic "…best represents this English sentence?" prompt. `question` is the sentence alone, and the logged `question_text` is the key plus that sentence; the scenario is recoverable from `translation_mode`, which already identifies the arm.
- **UX (2.1.4):** The footer's green "Distinguished Paper at CAV 2025" button, shown on every page of the tutor, is now a plain "CAV 2025 Paper" text link alongside Blog Post / Brown PLT / GitHub, pointing at the same paper. (The README, which addresses researchers rather than students, still names the award.)
- **UX (2.1.3):** Submitting the "Is this English sentence confusing or unclear?" report on an english-to-LTL question now acknowledges the feedback instead of silently closing the modal: a persistent note appears under the question ("Thank you for your feedback. Please answer with your best-guess interpretation of the sentence."), announced to screen readers via `role="status"`. A failed submission now alerts the student instead of logging only to the console.
- **UX (2.1.2):** Misconception explainers now show inline LTL operators and formulas in the learner's selected Classic, Forge, or Electrum syntax, updating immediately when the top-bar syntax choice changes. Explainer fragments are authored in Classic inside `<code class="ltlformula">` and rewritten client-side by token substitution — safe because the tutor grammar only permits lowercase atoms, so a bare `X`/`F`/`G`/`U` is always an operator.
- **Bugfix (2.1.2):** The precedence explainer claimed `a | b & c -> d` parses as `((a | b) & c) -> d`; the parser actually yields `(a | (b & c)) -> d` (binary operators bind `&` > `|` > `U` > `->` > `<->`, left-associative within a level). Separately, the Electrum rendering of `U` formulas rendered operands with the Forge renderer, so e.g. `(X p) U q` displayed `NEXT_STATE` where Electrum uses `AFTER`.
- **Experiment (2.1.1):** The english-to-LTL framing experiment now has three arms (one third each) instead of the 50/50 abstract/lights split: abstract, lights (concrete but *descriptive*), and a new deontic arm that frames the *same* formula as a document-access policy the student audits ("You are auditing access to a confidential document. Company policy: Whenever the document is open, the VPN must be connected."). Per the Wason selection-task literature, facilitation comes from deontic, violation-checkable rules rather than concrete content alone — so the lights arm becomes the mere-content control. The audit theme's four attributes (document open, clearance active, VPN connected, screen shared) are deliberately independent in a student's mental model: coupled only by the policy under test, never by physics, so every state assignment stays conceivable. Deontic phrasing places the obligation on consequents only ("is connected" → "must be connected"); triggers stay indicative. New responses log `translation_mode="contextualizeddeontic"`; the lights arm keeps its historical `"contextualized"` value and its exact wording, so earlier responses stay comparable.
- **Bugfix (2.1.1):** The `G(F x)` recurrence sentence ("It must keep being the case, over and over forever, that…") read as plain `G(x)` — continuous persistence — while `G(x)` appears among the generated distractors, so a student who parsed the English correctly could be marked wrong and logged with a spurious misconception. Both themed arms now carry the two quantifiers in separate phrases ("No matter how much time passes, eventually X"; deontic: "No matter how much time passes, X must eventually hold"). Lights-arm responses to `G(F x)` items logged before this fix should be segmented or dropped in per-condition analyses. Also removed double modals in the deontic renderings of `G(X x)` and `G(x U y)`.
- **Schema (2.1.1):** `misconception_attempts` now records `translation_mode` (added to existing deployments by the startup schema check), so per-arm misconception analyses can join opportunities → attempts directly instead of reconstructing the arm from legacy per-code response rows.
- **Bugfix (2.1.1):** Multiple-choice distractors could be semantically equivalent to *each other* (e.g. `G d` and `G (G d)` on a `G(F d)` item): mutations were checked against the answer but merged only by string equality. Options are now merged up to semantic equivalence (`LTLNode.equiv`), unioning their misconception codes, so no two displayed options denote the same property.
- **Tests (2.0.2):** Added a real-SPOT safety net and critical-path coverage; the suite grew from 192 to 284 tests and line coverage from ~50% to ~64%. Previously *every* test mocked SPOT, so `spotutils.py` — whose failures cause blank exercises / 500s in a live class — was never actually exercised. New `test/test_spotutils_realspot.py` runs against the real SPOT kernel (equivalence, trace satisfaction, trace generation round-trips, and the malformed-input failure contract), coexisting with the mocking suite via a cached-import helper (`test/realspot.py`) that imports the SPOT C-extension exactly once. Also added coverage for `feedbackgenerator.py` (0→100%), the per-step trace stepper (`test/test_stepper.py`, 0→80%), exercise option/question shuffling invariants across many seeds (`test/test_exerciseprocessor.py`), the Flask answer→feedback→log path with a throwaway SQLite DB (`test/test_exercise_flow_integration.py`), and logger idempotency + the distinct-question submission counter (`test/test_logger_db.py`).
- **Bugfix (2.0.2):** `syntacticmutator.changeBinaryOperator` / `changeUnaryOperator` (used to generate random answer distractors) indexed the full operator-subclass list with a position from the candidate list, so a mutation could return the *same* operator ~24% of the time (no real change) and could never reach certain operators (`<->`, `!`). They now instantiate the chosen operator directly, restoring full distractor diversity; regression-guarded by property-based tests in `test/test_syntacticmutator_pbt.py`.
- **Major redesign (2.0.1):** Replaced the one-directional “BKT-inspired” misconception weight with a versioned, option-aware evidence model. Each answer now records one idempotent attempt and explicit opportunities for only the misconception-coded distractors the question displayed. Selecting a coded distractor supplies bounded positive evidence; correctly rejecting a displayed distractor supplies guess-adjusted negative evidence; selecting a different wrong answer remains ambiguous. Merged distractors split their evidence across codes, random syntactic controls are excluded, and stale evidence decays toward the uncertain 0.5 prior. The displayed value is explicitly an uncalibrated evidence score rather than a probability.
- **Adaptive scheduling (2.0.1):** Separated misconception inference from practice selection. Distractor, focused trace yes/no, template, and operator-pool selection now use a monotonic policy with an exploration floor, so high-score misconceptions appear more often while resolved ones remain in occasional rotation. Operator scaling is deterministic and non-compounding, and intentionally disabled operators (including R) remain disabled. Legacy response rows remain available for reports but are not silently reinterpreted as structured opportunities.
- **Tests/docs (2.0.1):** Added the misconception evidence contract and BKT decision record, database/idempotency tests, synthetic positive/negative/decay sequences, seeded scheduling simulations, and property-based bounds/monotonicity coverage.
- **New:** LTL-to-English translation is now multi-sentence. A new prose translator (`ltltoeng_prose.py`) renders complex formulas as short requirements-style sentences with discourse connectives instead of forcing one long sentence, and is now used everywhere English is produced (english-to-LTL questions, the `/ltltoenglish` API and UI, the stepper). Its composition rules only attach verbs to atomic propositions and embed anything larger as a full clause, which eliminates the double-verb artifacts nested formulas used to produce (e.g. "'e' must hold at all times holds exactly when ..."). Grammar regression tests cover 38 formula shapes (`test/test_prose_translation.py`).
- **New:** Built-in abstract-vs-contextualized experiment for english-to-LTL questions (Wason-selection-task hypothesis: are logically equivalent statements easier to interpret when framed concretely?). Each adaptively generated english-to-LTL question is randomly assigned 50/50 to either abstract prose ("Whenever 'b' holds, 'a' must eventually follow") or a concrete colored-lights framing ("Whenever the blue light is on, then eventually the amber light is on") of the *same* formula — the contextualized arm renames the formula's literals onto the lights theme (blue/amber/purple/cyan, chosen so each literal is the color's first letter while avoiding operator-lookalike letters like `r`/`g`), so the two conditions differ only in framing. The condition is stored per response in a new `student_responses.translation_mode` column (added to existing databases by a startup migration), enabling per-condition accuracy analysis from ordinary tutor logs.
- **Tests (2.0.1):** The unit test suite is green and deterministic again. Four `test_english_translation.py` tests asserted pre-#119 behavior (capitalized raw `__to_english__()` fragments, the old "always hold" final-state wording) — they now test the finalized-sentence layer and the fluency-scored candidate invariants. Two `test_mutation.py` tests didn't account for randomness: the X-chain BadStateIndex cases (random ±1-2 Nexts) now accept every valid chain length, and the rewrite-location-diversity test no longer silently loses all mutations to the mocked-SPOT equivalence check (which returned a truthy MagicMock for "is this equivalent?") — it substitutes syntactic equality during the test.
- **New (2.0.1):** The student profile page now shows an "Adaptive Profile" — the live state the exercise engine uses to tailor questions: the current difficulty level (with a Beginner/Intermediate/Advanced band and how it moves), the question-type mix (making it visible that a student's weakest type is drilled more), and a misconception snapshot ranking the tutor's current per-misconception estimates (the values that drive which distractors appear). A new **Export Profile (JSON)** button downloads this state as a versioned `/profile/export` snapshot (complexity, question-type weights, misconception weights, and an accuracy summary). The snapshot logic lives in `ExerciseBuilder.get_profile_snapshot`, keeping the route thin.
- **New (2.0.1):** Multiple-choice questions now show at most 6 options (previously every applicable misconception became an option — up to ~10). When more misconceptions apply than fit, distractors are sampled weighted by the student's per-misconception weight, with a floor so a resolved misconception still appears occasionally (and can be measured back down). The syntactic red-herring control is always kept when one can be generated. Instructor distractor suggestions are unaffected.
- **New (2.0.1):** Question-type selection is now adaptive: question kinds are drawn weighted by the student's Laplace-smoothed per-type error rate instead of uniformly at random, with a 15% exploration floor so no type ever disappears. The number of atomic propositions in generated exercises also scales with the student's complexity band (2–3 literals at low complexity, up to 3–4 at high).
- **Bugfix:** Adaptive difficulty now actually persists. The per-user complexity was bumped inside `calculate_misconception_weights` but never written to the `generated_exercise.complexity` column, so `getComplexity` always returned `None` and every adaptation was discarded between requests. Complexity is now updated explicitly (`ExerciseBuilder.update_complexity`), can step **down** on struggle (recent accuracy ≤ 45%) as well as up on success (≥ 80%), is clamped to [3, 12], and is persisted with each generated exercise. Response history is deduplicated (wrong answers are logged once per misconception) before computing accuracy. The complexity model's invariants (bounds, single-step movement, the min-answers gate, accuracy thresholds, and convergence to the ceiling/floor for consistently strong/weak students) are covered by property-based tests (`test/test_complexity_pbt.py`, using Hypothesis).
- **Bugfix:** Fixed `console.err` typos in `checkanswers.js` that masked errors when updating answer counts.
- **UX:** The stepper link on wrong trace-satisfaction answers is now honestly labeled. Multiple-choice questions offer two clearly-labeled buttons — "See why your trace fails the formula" (selected trace + question formula) and "See why the correct trace satisfies the formula" (correct trace + question formula) — resolving a long-standing TODO about the ambiguous trace being passed.
- **New:** Trace-satisfaction questions now get real feedback on wrong answers (previously "No further feedback currently available"): the server evaluates the formula at every state of the relevant trace (the question's trace for y/n, the student's selected trace for multiple choice) and the trace is redrawn with per-state ✓/✗ marks showing where the formula holds.
- **UX:** Replaced the static Euler-diagram PNGs in english-to-LTL feedback with a live SVG renderer (`eulerdiagram.js`). Diagrams now show the actual selected and correct formulas in a color-coded legend, place a dot marking where the counterexample trace falls, and cover the equivalent-answer case (previously no visual).
- **Accessibility:** Removed the raw spot-syntax "Alt Trace" text from feedback; trace SVGs now carry a natural-language per-state `aria-label` instead.
- **Bugfix:** Fixed a missing space in the "more restrictive" feedback message.
