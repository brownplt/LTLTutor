Fan Out Operators Review

You might think that the {{ ltl_code('F p', operator_only=True) }}, {{ ltl_code('G p', operator_only=True) }}, and {{ ltl_code('p U q', operator_only=True) }} operators behave in a way that limits their effects to just one state. However, each of these operators is designed to 'fan out' over a sequence of states, influencing how conditions are satisfied over time.

  • {{ ltl_code('F p') }} guarantees that the proposition {{ ltl_code('p') }} will hold true at least once in the future. It doesn't specify when, just that it will happen, potentially even in the current state. For example, {{ ltl_code('F p') }} means that {{ ltl_code('p') }} could be true now or at any future moment.
  • {{ ltl_code('G p') }} asserts that the proposition {{ ltl_code('p') }} must hold in all states, starting from the current state and continuing indefinitely. {{ ltl_code('G p') }} means {{ ltl_code('p') }} is required to be true not just now but in every future state as well.
  • {{ ltl_code('p U q') }} specifies that {{ ltl_code('p') }} holds in every state until {{ ltl_code('q') }} becomes true. Crucially, {{ ltl_code('q') }} must eventually become true for the formula to be satisfied.
If you find yourself swapping these operators or using them incorrectly, focus on what each specifically dictates about the states where the conditions must be met. For example, swapping {{ ltl_code('F p', operator_only=True) }} and {{ ltl_code('G p', operator_only=True) }} would mean changing from an event that happens at least once to a condition that must always hold. These are very different requirements!
